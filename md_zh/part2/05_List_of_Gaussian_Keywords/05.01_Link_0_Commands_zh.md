### 5.1 Link 0 命令

本节列出所有 Link 0 命令。这些命令是可选的,位于路由段之前。

Link 0 命令长度最多可为 500 个字符。

**%Mem=_N_**

将动态内存用量设置为 *N* 个 8 字节字(默认)。该数值后面还可以紧跟 KB、MB、GB、TB、KW、MW、GW 或 TW(中间不留空格),分别表示千、兆、吉、太字节或字。默认内存大小为 800 MB。可以通过 *Default.Route* 中的 -M- 指令设置不同的默认值。

**%Chk=_file_**

指定并命名检查点文件。

**%OldChk=_file_**

在作业步开始时,将 %OldChk 指定的检查点文件内容复制到当前作业步的检查点文件中。这样可以从之前的计算中获取数据,而不会破坏当前检查点文件上的内容。

**%SChk=_file_**

在作业步开始时保存检查点文件的副本。通常可以用 %OldChk 与 %Chk 实现相同的效果,但有时以这种方式保存中间结果会更方便。

**%RWF=_file_**

指定并命名单一的统一读写文件(旧式语法)。

**%RWF=_loc1_,_size1_,_loc2_,_size2_,**···

这是一种替代语法,可将读写文件分布到两个或多个磁盘(或文件系统)上。每个位置后面跟随该位置文件段的最大大小。文件段大小默认以 8 字节字为单位。该数值后面还可以紧跟 KB、MB、GB、TB、KW、MW、GW 或 TW(中间不留空格),分别表示千、兆、吉、太字节或字。任一大小参数取值为 -1 表示可以使用任何及全部可用空间,取值为 0 表示现有段保持其当前大小。位置可以是目录位置或完整路径名。注意,目录说明在 UNIX 系统上*必须*以斜杠结尾。

**%OldMatrix=_matfile_**

在作业步开始时,将未格式化二进制矩阵元素文件 *matfile* 中的数据复制到活动检查点文件中。该指令与 %OldChk 类似,但数据取自指定文件。在 Rev. B.01 及更高版本中,文件名后可以跟随关键字 i4lab,表示该文件使用 4 字节整数,例如:%OldMatrix=(myfile,i4lab)。

**%OldRawMatrix=_matfile_**

在作业步开始时,将原始二进制矩阵元素文件 *matfile* 中的数据复制到活动检查点文件中。该指令与 %OldChk 类似,但数据取自指定文件。在 Rev. B.01 及更高版本中,文件名后可以跟随关键字 i4lab,表示该文件使用 4 字节整数,例如:%OldRaw=(myfile,i4lab)。

**%Int=_spec_**

指定并命名双电子积分文件。*spec* 参数可采用与读写文件相同的任一形式。

**%D2E=spec**

指定并命名双电子积分导数文件。*spec* 参数可采用与读写文件相同的任一形式。

**%KJob L _N_ [_M_]**

告诉程序在 Link *N* 第 *M* 次出现后停止运行。例如,%KJob L502 2 会使运行在 Link 502 第二次运行后终止。*M* 可省略,默认为 1。

**%Save**

使 Link 0 在运行结束时保存临时文件。默认情况下,所有未指定的临时文件都会被删除,而所有已命名的临时文件在运行成功完成时都会被保存。

**%ErrorSave**

使 Link 0 在运行成功结束时删除临时文件,包括*在该指令之前*已显式命名的文件。换言之,若某文件在遇到 %ErrorSave 之前已被命名,则不会被保存;但若命名该文件的指令出现在 %ErrorSave 之后,则该文件会被保留。如果作业异常结束,则所有文件都会被保存。%NoSave 是该指令的同义词。若同时指定了 %Save 和 %ErrorSave,则以输入文件中位置靠后者为准。

**%Subst L _N dir_**

告诉 Link 0 从其他目录中获取某个 Link 的可执行文件(.exe 文件)。例如,%SUBST L913 /user/chem 会运行 /user/chem/l913.exe,而不是默认的可执行文件(位于 $g16root 中)。目录说明应采用所用机器的常用格式。只能指定目录;文件名必须采用标准形式 l*nnnn*.exe,其中 *nnnn* 为 Link 编号。

#### 5.1.1 并行作业指令

**%CPU=_proc-list_**

该指令包含用于共享内存并行处理的处理器/核心编号列表,多个项目之间以逗号分隔。该指令旨在取代早期的 %NProcShared 和 %NProc 指令。可以通过 *Default.Route* 中的 -C- 指令设置默认值。

**%NProcShared=_N_**

请求作业在 SMP 多处理器计算机上以共享内存并行方式使用最多 *N* 个处理器/核心。在大多数情况下,该指令已被 %CPU 取代。%NProcShared 的值会覆盖 *Default.Route* 文件中的 -P- 指令。

**%GPUCPU=_gpu-list=core-list_**

设置默认使用的 GPU 列表。使用 GPU 时,每个 GPU 必须由特定 CPU 控制,并且最好该 CPU 在物理上靠近其所控制的 GPU。等号前的列表指明计算所用的 GPU。第二个列表中的对应项指定每个 GPU 绑定到的核心。例如,下面的指令让 Gaussian 在 GPU0 至 GPU3 上执行:

```
%GPUCPU=0,1,2,3=0,1,16,17
```

GPU0 和 GPU1 绑定到核心 0 和 1,而 GPU2 和 GPU3 分别绑定到核心 16 和 17。该指令中可以使用 GPU 和/或核心的范围。例如,下面的写法与上面等价:

```
%GPUCPU=0-3=0-1,16-17
```

可以通过 *Default.Route* 中的 -G- 指令设置 %GPUCPU 的默认值。

**%LindaWorkers=_node1_[:_n1_] [,_node2_[:_n2_]]** ···

列出每个要使用的节点的 TCP 节点名。默认情况下,每个节点上启动一个 Linda 工作进程,但可选的数值可用于改变这一数量。无论主节点是否出现在节点列表中,总会在作业启动的节点(主节点)上启动一个工作进程。可以通过 *Default.Route* 中的 -W- 指令设置默认值。%LindaWorkers 可以与 %NProcShared 结合使用。此时,每个节点上将运行一个或多个并行工作进程(数量仍由 %LindaWorkers 的取值决定)。%NProcShared 的值指定工作节点列表中每个系统上使用的 SMP 处理器/核心数。请勿使用已废弃的 %NProcLinda 指令。Gaussian 将根据 %LindaWorkers 的输入计算 Linda 工作进程总数。

**%UseSSH**

使用 ssh 而非 rsh 启动 Linda 工作进程。%UseRSH 表示使用 rsh,它是默认值。可以通过 *Default.Route* 中的 -S- 指令设置不同的默认值。

**%DebugLinda**

报告有关启动和停止 Linda 工作进程的详细信息。

#### 5.1.2 示例

这些命令为检查点文件指定了名称,为另一个读写文件指定了替代名称和目录位置,并使 Gaussian 作业结束时只保存检查点文件:

```
%RWF=/chem/scratch2/water Files to be deleted go here.
%NoSave
%Chk=water Files to be saved go here.
```

下面的指令使网络并行作业在指定的 5 个节点上运行。节点 *hamlet* 和 *ophelia* 各运行两个工作进程:

```
%LindaWorkers=hamlet:2,ophelia:2,laertes,horatio,lear
```

下面的指令指定并行作业将在主机 *norway*、*italy* 和 *spain* 上执行。节点 *norway* 和 *italy* 各运行一个 4 路 SMP 并行工作进程,而 *spain* 运行两个此类工作进程:

```
NProcShared=4 Specifies four-way SMP parallelism.
%LindaWorkers=norway,italy,spain:2
```

只有当 *norway* 和 *italy* 为 4 处理器/核心计算机,而 *spain* 为 8 处理器/核心计算机时,这些指令才有意义。
