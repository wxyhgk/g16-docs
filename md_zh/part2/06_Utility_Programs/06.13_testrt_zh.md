### 6.13 testrt(路由段测试工具)

testrt 是一个实用程序,它接受标准 Gaussian 路由段作为输入,并生成等效的非标准路由段。路由段通常在命令行中指定(并用引号括起):

**$ testrt "# rhf/sto-3g"**

若命令行中未包含路由段,testrt 将提示输入待测试的路由段。若所指定的路由段有效,testrt 将打印出与之对应的非标准路由段。若存在语法错误,则会显示错误信息。因此,即使是不了解非标准路由段的用户,也可以用 testrt 验证路由段的语法正确性。

#### 6.13.1 示例

以下是 testrt 的几个运行示例:

**$ testrt "# ccsd(modredun)/6-31G* scf=driect"**

```
----------------------------------
#ccsd(modredun)/6-31G*scf=driect
----------------------------------
QPErr — - A syntax error was detected in the input line.
# ccsd(modredundant) ModRedundant is a valid option, but not for CCSD.
’
```

**$ testrt "mp4 nmr"***NMR 不适用于 MP4。*

```
-------
mp4nmr
-------
NMRonlyforHF,DFT,andMP2.
```

**$ testrt**

```
Pleasetypeintheroutespecification,terminatedwithablankline:
```

**# HF/6-31G(d) Opt=QST2**

*testrt 输入结束。*

```
----------------------
#HF/6-31G(d)Opt=QST2
----------------------
1/5=1,18=20,27=202,38=1/1,3;
2/9=110,12=2,17=6,18=5,40=1/2;
```

···

如第一个示例所示,仅会标记路由段中的第一个错误。第二个示例说明了无效关键字组合所产生的错误信息。最后一个示例显示了路由段测试成功时的输出。请注意,testrt 无法检测关键字使用错误;它只检查所给路由段的语法。因此,它不会警告您在路由段中两次包含 MP2 关键字会产生意外结果(实际运行的是 MP4 作业)。testrt 的输出可以通过标准 UNIX 输出重定向保存到文件中:

**$ testrt "# rhf/sto-3g" >***output-file*
