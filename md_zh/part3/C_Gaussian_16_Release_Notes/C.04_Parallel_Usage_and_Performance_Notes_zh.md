### C.4 并行使用与性能说明

#### C.4.1 共享内存并行

**内存分配。** 涉及较大分子与基组的计算会从更大的内存分配中获益。对于涉及 50 个或更多原子和/或 500 个或更多基函数的计算,建议每个处理器分配 4 GB 或更多内存。freqmem 工具可估算基态频率计算每个线程的最佳内存大小;同样的数值对激发态频率也较为合理,并且对于基态与激发态优化而言已绰绰有余。

所允许的内存量应随处理器数量增加:若单个处理器使用 4 GB 较为合适,则使用 8 个 CPU 运行同一作业时,32 GB 即可良好运行。当然,特定硬件可能对较小的数值有所限制,但应使内存与 CPU 数量呈线性比例增长才是目标。特别地,在内存大小固定的情况下仅增加 CPU 数量,在使用大量处理器时不太可能获得良好的性能。

对于大型频率计算以及大型 CCSD 和 EOM-CCSD 能量计算,还应留出足够的内存来缓冲所涉及的大型磁盘文件。因此,一个 Gaussian 作业通常只应分配系统总内存的 50–70%。例如,在总内存为 128 GB 的机器上,对于使用全部 CPU 的作业,通常应分配 64–80 GB,并将剩余内存留给操作系统用作磁盘缓存。

**在 Linux 下将线程绑定到 CPU。** 当线程在不同 CPU 之间迁移时,缓存会失效并产生其他开销,从而损失效率。在大多数机器上,Gaussian 可以将线程绑定到特定 CPU,这是推荐的运行模式,尤其是在使用大量处理器时。%CPU Link 0 行用于指定所使用的特定 CPU 编号。因此,在一块 8 核芯片的机器上,应使用 %CPU=07 而非 %NProc=8,因为前者将第一个线程绑定到 CPU 0,下一个绑定到 CPU 1,依此类推。

在一些较老的 Intel 处理器(Nehalem 及更早)上,内存带宽不足以使芯片上的所有 CPU 保持繁忙,此时通常最好只使用一半的 CPU,并使每个 CPU 分得的内存为使用全部 CPU 时的两倍。例如,在一台具有四块 12 核芯片且内存为 128 GB 的机器上,CPU 0–11 位于第一块芯片,12–23 位于第二块,依此类推,则最好使用 24 个处理器(每块芯片 6 个)运行,并分配 72 GB / 24 进程 = 每个进程 3 GB 内存,而不是使用全部 48 个处理器、每个仅 1.5 GB 内存。所需的输入指令为:

```
%Mem=72GB
%CPU=0-47/2
```

其中 /2 表示每隔一个核心使用一次,即:芯片 0 上的核心 0、2、4、6、8、10,芯片 1 上的核心 12、14、16、18、20、22,依此类推。

对于最新一代的 Intel 处理器(Haswell 及之后),内存带宽更好,使用每块芯片上的全部核心效果良好。

只要内存充足且线程绑定到特定核心,则对于大分子而言,并行效率在 64 个或更多核心上仍然良好。

**禁用超线程。** 超线程对 Gaussian 没有帮助,因为它会在同一物理 CPU 上的线程之间有效地划分内存带宽等资源。若无法关闭超线程,则 Gaussian 作业应在每个物理 CPU 上只使用一个超线程。在 Linux 下,不同处理器上的超线程会被归为一组。也就是说,若一台机器有 2 块各含 8 个核心且为三路超线程的芯片,则"CPU"0–7 分布于芯片 0 的 8 个核心上,8–15 分布于芯片 1 的 8 个核心上,16–23 为芯片 0 的 8 个核心上的第二个超线程,依此类推。因此,作业以 %CPU=015 运行效果最佳。

在 AIX 下,即使使用的超线程数较少,超线程也会按每个 CPU 最多 8 个超线程编号进行分组。因此,对于两块 8 核芯片且为四路超线程的机器,"CPU"0–3 均位于芯片 0 的核心 0 上,8–11 位于芯片 0 的核心 1 上,依此类推。于是,应使用 %CPU=0127/8 选择 "CPU" 0、8、16、…,它们各自使用一个不同的核心。

#### C.4.2 集群(Linda)并行

**可用性。** Hartree-Fock 与 DFT 的能量、梯度与频率可以跨集群并行运行,MP2 能量与梯度亦然。MP2 频率、CCSD 与 EOM-CCSD 能量及优化则为 SMP 并行,但不支持集群并行。数值导数(例如 DFT 非简谐频率与 CCSD 频率)通过在集群的每个节点上完整地进行梯度或二阶导数计算,并将微分方向分配给集群中的各工作进程,从而在节点之间实现并行。

**与 MP 并行结合。** 共享内存并行与集群并行可以结合使用。通常,在集群的每个节点内,对所有 CPU 使用共享内存并行。请注意,%CPU 与 %Mem 作用于集群的每个节点。因此,若有 3 个名为 *apple*、*banana* 和 *cherry* 的节点,每个节点含两块各有 8 个 CPU 的芯片,则可以这样指定:

```
%Mem=64GB
%CPU=0-15
%LindaWorkers=apple,banana,cherry
```

`# B3LYP/6-311+G(2d,p) Freq`···

这将在 3 个节点上各运行 16 个线程,每个线程绑定到一个 CPU,并为 48 个线程中的每一个分配 4 GB 内存。对于仅进行数值微分的特殊情形(例如 Freq=Anharm、CCSD Freq 等),会额外使用一个工作进程来收集结果。因此,这类作业应在启动 Gaussian 16 的主节点上运行两个工作进程。对于上述示例,若作业计算的是非简谐频率,则应使用:

```
%Mem=64GB
%CPU=0-15
%LindaWorkers=apple:2,banana,cherry
```

`# B3LYP/6-311+G(2d,p) Freq=Anharm`··· 假定 Gaussian 16 在节点 *apple* 上启动。这将在节点 *apple* 上启动 2 个工作进程,其中一个仅负责收集结果,而计算工作则由 *apple* 上的另一个工作进程以及 *banana* 和 *cherry* 上的工作进程完成。
