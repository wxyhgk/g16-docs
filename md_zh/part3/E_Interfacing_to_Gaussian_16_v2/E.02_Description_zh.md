### E.2 描述

过去,一些用户通过将其程序的可执行文件与 Gaussian 的库进行链接,或者让其代码在 Gaussian 链接中被调用,来使用 Gaussian 的功能。然而,这种做法在许多方面都存在问题。它要求获得 Gaussian 的源代码,要求用户使用与 Gaussian 相同的编译器和选项来编译自己的代码,还要求用户理解 Gaussian 内部的数据结构和调用约定。这使得生成的代码十分脆弱:Gaussian 未来版本中对普通用户透明的内部改动,可能会破坏用户的代码。此外,这种做法还在代码归属和知识产权方面带来了不必要的复杂性。

#### E.2.1 通用接口的目标

我们对通用接口的目标是:以清晰且易于维护的方式支持上述所有用途。它应当做到:

- 允许其他程序或脚本与标准 Gaussian 二进制程序通信,无需重新编译、修改 Gaussian,也无需访问 Gaussian 源代码。
- 对用户尽可能简单,特别是提供一种无需了解 Gaussian 内部数据结构或算法的接口,并且尽可能少地要求用户了解接口文件的内部结构。
- 具有自描述性且向上兼容,使得在添加新的数据类型和新功能时,不会破坏使用旧版本接口编写的用户代码。
- 便于将 Gaussian 用作主控程序或从属程序。
- 尽可能不以 Gaussian 为中心,以便使用 Gaussian 接口的代码也能够使用其他提供相同接口的量子化学程序。此前,我们提供了格式化检查点文件作为接口机制,特别用于对 Gaussian 的计算结果进行后处理。该文件目前仍受支持且可用,它是自描述且可扩展的。

作为普通文本文件,它的格式相对简单,便于处理。然而,尽管这种设计适合对 Gaussian 结果进行后处理,尤其是用于可视化,但由于两个原因,它并不足以作为通用接口:其一,数值存储的精度有限,不足以满足积分等中间数据的需求;其二,当涉及大量数据时,由于需要在文本形式与二进制形式之间进行转换,读写该文件的开销很大。此外,由于该文件最初是为后处理以及在不同类型硬件上运行的 Gaussian 之间迁移数据而设计的,它在很大程度上照搬了 Gaussian 内部的数据结构。

#### E.2.2 通用接口的结构

新接口包含三个基本组成部分:

- 一种自描述但相对紧凑的二进制数据文件,它尽量以简单的形式存储标准数据,而不是使用 Gaussian 的内部数据结构。这些形式既支持 Fortran 无格式形式(适用于与 Fortran 或 Python 编写的程序对接),也支持原始二进制数据(适用于 C、C++ 和 Perl 程序)。两种文件中的数据组织方式相同。文件结构的详细信息见 *矩阵元文件*。formchk 和 unfchk 实用程序可以在 Gaussian 检查点文件与这两种类型的二进制接口文件之间进行转换。
- Gaussian 内部的功能,可将此类二进制数据文件用作完整 Gaussian 作业的输入或输出,以及用作 Gaussian 与其内部运行的外部程序之间的输入/输出。从属程序通过 External 接口与 Gaussian 相连。此类程序可用于:
  - 替代 Gaussian 的 SCF 链接。
  - 作为使用 Gaussian 内生成的轨道进行的 SCF 后步骤。
  - 计算导数,用于由 Gaussian 控制的几何优化和频率计算。
  - 执行 ONIOM 模型中的一个或多个子计算。Gaussian 也可以作为从属程序运行,其全部或大部分输入来自控制程序提供的数据文件,并生成包含其计算结果的新数据文件。
- 提供便捷接口的库和脚本,用于读写这些文件。它们是开源的,因此可以很容易地并入用户程序。随着需要更多功能,该接口将持续演进。目前数据文件中可用的量包括 SCF 及 SCF 后计算中最常用的量,例如原子的位置与种类、基组、原子轨道上的单电子和双电子积分、分子轨道系数以及分子轨道上的双电子积分。

#### E.2.3 关于接口库和脚本

各开源接口库和脚本的成熟程度因其目前的使用范围而异:

- Fortran 接口例程(位于 *qcmatrix.F* 和 *qcmatrixio.F* 中)可以方便地从文件中读写数据,使用者只需了解很少的文件结构。Fortran 接口已在 PGI、Gnu 和 Intel Fortran 编译器上测试通过。
- Python 模块通过 **f2py** 导入 Fortran 接口,并增加了更高层的功能,包括针对文件中各个条目(原子坐标、算符矩阵等,位于 *QCOpMat.py* 中)的对象接口,以及针对整个文件的对象接口(位于 *QCMatEl.py* 中)。除了读写文件之外,文件对象还提供了透明地运行 Gaussian 以生成额外数据的方法,因此 Python 用户无需了解 Gaussian 的输入语法,也无需了解磁盘上接口文件的结构,即可请求并使用 Gaussian 的计算结果。文件中的实际数据以 **NumPy** 数组形式存储,因此可直接用于 **NumPy** 和 **SciPy** 例程。Python 接口使用了许多 Python3 的特性,不支持 Python2。

- Perl 模块(*OpMat.pm* 和 *MatEl.pm*)以与 Python 模块相同的风格,为数据条目和整个文件提供透明的对象接口,但不包含全部高层功能。

所有接口的详细信息见源文件中的注释。

接口例程假定数据文件中的整数为 4 字节。对于文件的原始形式,必须假定固定的整数大小,因为在读取文件时无法可靠地确定该大小。由于 Perl 和 Python 目前都使用 32 位寻址,且无法处理超过 2 GB 的数组,因此对这些语言而言这不构成限制。Fortran 接口例程同时提供 4 字节和 8 字节整数的版本(后者在文件名后附加 8)。

目前没有单独的 C 接口库;根据具体情况,C 代码既可以使用与 Perl 模块相同的逻辑读取原始二进制文件,也可以调用 Fortran 接口例程。由于从 C 或 C++ 调用 Fortran 的细节取决于具体的操作系统和编译器,我们尚未对此进行标准化。

#### E.2.4 在 Gaussian 中生成接口数据文件

二进制矩阵元文件可以通过以下三种方式生成:

- 使用 formchk 实用程序,将 Gaussian 作业结束后留下的二进制检查点文件转换为该格式。
- 使用在 Gaussian 计算中通过 External 关键字运行的外部脚本或程序。
- 使用 Output=MatrixElement 或 Output=RawMatrixElement 关键字,使文件在当前 Gaussian 作业步骤结束时生成。

格式化检查点文件同样可以通过以下三种方式生成:

- 使用 formchk 实用程序,将 Gaussian 作业结束后留下的二进制检查点文件转换为该格式。
- 当 Gaussian 中的计算需要运行外部脚本或程序时生成(参见 External)。
- 在 **g16** 命令行中使用 **-fchk** 开关,这会在作业步骤的每个“关键”点(如优化过程中出现新几何构型时、作业步骤结束时等)写入或重写格式化检查点文件。

#### E.2.5 将数据文件用作 Gaussian 的输入

格式化检查点文件或二进制矩阵元文件,都可以通过转换为二进制检查点文件后用作 Gaussian 的输入。这需要使用 unfchk 实用程序完成。随后,通过 %Chk 或 %OldChk Link 0 命令指定所生成的二进制检查点文件名,即可将其提供给 Gaussian 作业步骤。

此外,还可以通过 %OldMatrixElement 或 %OldRawMatrixElement Link 0 命令将矩阵元文件指定为输入。这些命令会从矩阵元文件中读取数据,并将其移入当前作业步骤的检查点文件中,从而可用于提供几何构型、初始波函数等信息。

#### E.2.6 从其他程序中运行 Gaussian

至少有两种方式可以实现这一点:

- 其他程序可以生成一个 Gaussian 输入文件。该输入文件指定 Gaussian 从数据文件读取输入和/或生成包含其计算结果的数据文件。随后,控制程序可以使用 UNIX 系统命令、fork/exec 机制或同等功能,在子进程中运行 Gaussian。
- Python 接口(*QCMatEl.py*)提供了一个矩阵元类,其中包含可自动运行 Gaussian 并使用附加数据更新矩阵元对象的方法。这既可以被 Python 程序直接使用,也可以由其他语言编写的程序创建一个子进程,运行一个简单的 Python 脚本,再由该脚本运行 Gaussian。
