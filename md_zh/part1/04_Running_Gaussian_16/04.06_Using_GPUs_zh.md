### 4.6 使用 GPU

Gaussian 16 可以在 Linux 下使用 NVIDIA K40、K80 和 P100 GPU(后者自 Rev. B.01 起支持)。更早的 GPU 在计算能力或显存容量上不足以运行 Gaussian 16 的算法。

#### 4.6.1 为作业分配内存

使用 GPU 时,为作业分配足够的内存比使用 CPU 时更加重要,因为必须同时处理更大的任务批次才能高效利用 GPU。K40 和 K80 最多可配备 16 GB 显存。通常应将其中大部分分配给 Gaussian。当每块 GPU 总显存为 12 GB 时,为 Gaussian 分配 8–9 GB 效果良好;同样,对于 16 GB 的 GPU,分配 11–12 GB 较为合适。此外,每个控制 GPU 的 CPU 线程至少还需要等量的可用内存。

#### 4.6.2 关于控制 CPU

使用 GPU 时,每块 GPU 必须由一个特定的 CPU 控制。控制 CPU 应尽可能在物理位置上靠近其所控制的 GPU。GPU 不能共享控制 CPU。*注意,用作 GPU 控制器的 CPU 不能同时用作计算节点。* 可以使用 **nvidia-smi** 工具查看含 GPU 系统的硬件配置。例如,以下输出来自一台配备两颗 16 核 Haswell CPU 芯片和四块 K80 板卡(每块板卡含两块 GPU)的机器:

#### 4.6.3 为 Gaussian 作业指定 GPU 与控制 CPU

用于计算的 GPU 及其控制 CPU 通过 %GPUCPU Link 0 命令指定。该命令接受一个参数:%GPUCPU=*gpu-list=control-cpus*,其中 gpu-list 为以逗号分隔的 GPU 编号列表,可包含数值范围(例如 **0-4,6**),control-cpus 为格式相似的控制 CPU 编号列表。两个列表中对应位置的项即为某块 GPU 及其控制 CPU。例如,在一台具有 32 个处理器和 6 块 GPU 的系统上,若作业要使用全部 CPU——其中 26 个 CPU 参与计算,6 个 CPU 用于控制 GPU——则应使用以下 Link 0 命令:`%CPU=0-31` *控制 CPU 同样包含在此列表中。*

```
%GPUCPU=0,1,2,3,4,5=0,1,16,17,18,19
```

这些命令表明,作业将使用 CPU 0–31(但并非所有 CPU 都用于计算)。将使用 GPU 0 至 5,其中 GPU0 由 CPU 0 控制,GPU1 由 CPU 1 控制,GPU2 由 CPU 16 控制,GPU3 由 CPU 17 控制,依此类推。注意,控制 CPU 同样包含在 %CPU 中。在上例中,GPU 和 CPU 列表可以更简洁地表示为:

```
%CPU=0-31
%GPUCPU=0-5=0-1,16-19
```

通常以直观的方式使用连续编号的处理器,但在特殊情况下,对应关系可能有所不同。例如,假设同一台机器上已有一个使用 6 个 CPU、以 %CPU=16-21 运行的作业。那么,为了用其余 26 个 CPU 配合 6 块控制 GPU 运行作业,应指定:

```
%CPU=0-15,22-31
%GPUCPU=0-5=0-1,22-25
```

该作业共使用 26 个处理器,其中 20 个用于计算,并由分别被 CPU 0、1、22、23、24 和 25 控制的六块 GPU 协助。在 [**REV B**] 中,CPU 列表与 GPU 列表均经过排序后再进行配对。这确保编号最低的线程运行在带有 GPU 的 CPU 上。这样一来,若计算的某部分因内存限制而需要减少所用处理器数目,程序会优先使用或保留带有 GPU 的线程(因为它会按逆序移除线程)。

#### 4.6.4 GPU 与作业整体性能

在进行 DFT 能量、梯度和频率计算(包括基态和激发态)时,GPU 对较大分子效果显著,但对小作业则效果不佳。在 SCF 后计算(如 MP2 或 CCSD)中,GPU 也未能得到有效利用。每块 GPU 的速度是 CPU 的数倍。然而,在现代计算机上,CPU 数量通常远多于 GPU。最佳性能来自同时使用全部 CPU 与 GPU。在某些情况下,由于 Gaussian 16 也能有效利用大量 CPU,GPU 带来的潜在加速可能受到限制。例如,若 GPU 比 CPU 快 5 倍,则相对于仅使用 CPU,使用 GPU 的加速比为 5 倍。然而,在一台拥有 32 个 CPU 和 8 块 GPU 的较大计算机上,使用 GPU 的潜在加速比仅为 2 倍:*不使用 GPU*:32*1 = 32 *使用 GPU*:(24*1) + (8*5) = 64 *请记住,控制 CPU 不用于计算。* *加速比*:64/32 = 2

GPU 最多可配备 16 GB 显存。通常应尽量将其大部分分配给 Gaussian。请注意,运行每块 GPU 的 CPU 线程所获分配的内存,至少须与用于计算的内存相等。在 12 GB 的 GPU 上使用 8–9 GB 效果良好,在 16 GB 的 GPU 上使用 11–12 GB(保留部分内存供系统使用)。由于 Gaussian 将内存平均分配给每个线程,因此总内存应等于线程数乘以高效使用一块 GPU 所需的内存量。例如,当使用 4 个 CPU 和 2 块各配备 16 GB 显存的 GPU 时,应使用 4

- 12 GB 的总内存。例如:

```
%Mem=48GB
%CPU=0-3
%GPUCPU=0-1=0,2
```

在决定使用哪些处理器和 GPU 以及为计算分配多少内存时,您需要仔细分析自身环境的特点。

#### 4.6.5 集群中的 GPU

可以使用集群中节点上的 GPU。由于 %CPU 和 %GPUCPU 设置会应用于集群中的每个节点,因此各节点的配置(GPU 数量及其与 CPU 的亲和性)必须相同;由于大多数集群由相同的节点组成,这通常不成问题。
