### 4.9 Default.Route 文件

根据特定计算机系统的特点,出于性能考虑,有时需要覆盖程序内置的某些默认值。这可以通过创建自定义文件来实现。在基于 UNIX 的系统上,该文件名为 *Default.Route*,位于 $g16root/g16 中。在 Windows 下,Gaussian 默认值文件为 Default.Rou,位于 Gaussian 16W 的 scratch 子目录中(例如 C:\G16W\scratch)。该文件的格式在所有计算机系统上都相同。以下小节描述了可在默认值文件中提供的信息类型。

#### 4.9.1 说明

路由段默认值

这些参数由 -#- 引导,其形式与普通路由段命令相同。例如,下面这一行会将默认 SCF 算法设置为传统(非直接)算法:

```
-#-SCF=Conventional
```

文件中可以有多行 -#-。*Default.Route* 中列出的命令只改变默认值;输入文件路由段中指定的任何内容都会覆盖它们。因此,如果 *Default.Route* 包含:

```
-#-MP2=NoDirect
```

而输入文件的路由段包含 MP2 关键字,则将使用传统 MP2 算法。但如果路由段包含 MP2=Direct 关键字,则将使用直接算法。指令 -R- 是 -#- 的同义词。

最大磁盘用量

通常需要通过 *Default.Route* 文件中的 MaxDisk 关键字指定可用的临时磁盘空间。例如,下面这一行将 MaxDisk 设置为 2 GB:

```
-#-MaxDisk=2GB
```

默认情况下,可用磁盘空间以 8 字节字为单位。该数值后面还可以紧跟 KB、MB、GB、TB、KW、MW、GW 或 TW(中间不留空格),分别表示千、兆、吉、太字节或字。临时磁盘空间默认不受限制,即 MaxDisk=-1。换言之,程序假定有足够的磁盘空间可以完成给定计算且无冗余工作。因此,指定可用内存和磁盘是优化计算性能最重要的方式。这样做可以让程序在各种可用算法中做出选择,为您的系统配置挑选最优算法。请记住,可用磁盘空间越大,计算速度越快,对 MP2 尤其如此。

内存默认值

不合理地占用过多内存的 Gaussian 作业可能会对系统造成严重问题。内存指令 -M- 用于强制设定默认动态内存上限。例如,下面这一行将默认

内存用量设为 3GB:

```
-M-3GB
```

可用内存默认以 8 字节字为单位;该数值后面同样可以紧跟 KB、MB、GB、TB、KW、MW、GW 或 TW(中间不留空格),分别表示千、兆、吉、太字节或字。默认内存大小为 800 MB(100 MW)。请注意,该上限可以被 %Mem Link 0 命令覆盖。内存指令 -U- 用于设置 formchk、freqchk 等实用程序中使用的默认内存。

单位与主机名

主机名可用 -H- 设置;其值指定 Gaussian 生成的归档条目中使用的主机名。默认为当前主机名。单位/站点名可用 -O- 设置;其值指定 Gaussian 生成的归档条目中使用的站点名。默认无。

用户默认值文件 Gaussian 用户可以通过创建自己的 *Default.Route* 文件来设置个人默认值。作业启动时,Gaussian 会检查当前工作目录中是否存在该名称的文件。本地文件中的设置优先于站点范围文件中的设置,而作业路由段中指定的选项优先于这两者。

命令行选项与环境变量等价形式

以上所有指令也可以通过环境变量或 UNIX/Linux 命令行参数设置。环境变量 GAUSS_*x*DEF 提供了与 *Default.Route* 中 -X- 等价的命令行形式。同样,g16 的命令行参数 -*x*="value" 指定相同的设置。例如,以下写法效果相同:

```
-M- 4GB in Default.Route
exportGAUSS_MDEF=4GB
g16 -m="4GB" ···
```

优先级顺序

优先级顺序为:

- 命令行参数
- 环境变量
- *Default.Route* 设置
- 程序内部默认值

Default.Route 限制 并非所有路由段关键字都会在 *Default.Route* 文件中生效。总体规则是,特定于某一作业类型的选项会被忽略。因此,改变默认积分格点的 Integral=SuperFine 会生效,而为特定作业类型设置的 Freq=Raman 则会被忽略。

#### 4.9.2 并行作业指令

共享内存多处理器上的并行执行

Gaussian 默认仅在单个处理器上执行。如果您的计算机系统具有多个处理器/核心,且您所用版本的 Gaussian 支持并行处理,您可以使用 -C- 指令指定运行所用的具体 CPU。例如,下面的指令指定程序应在六核系统的前 5 个核心上运行(保留一个核心供其他用途):

```
-C-0,1,2,3,4
```

节点列表也可以写成范围(例如 0-5)。范围后还可以加上形式为 /*n* 的后缀,表示使用该范围内每第 *n* 个处理器(例如 /2 表示每隔一个处理器/核心)。较旧的 -P- 指令可用于指定执行所用的处理器总数(具体选择哪些处理器由操作系统决定)。显然,请求的处理器数不应超过可用处理器数,否则性能会大幅下降。

网络/集群并行执行

可以通过 -W- 指令在 *Default.Route* 中指定 Linda 工作进程列表:

```
-W-dalton,lavoisier:2,priestley,agassiz:3,curie
```

该示例将使用指定的五个节点进行并行计算,在 *lavoisier* 上放置 2 个工作进程,在 *agassiz* 上放置 3 个工作进程,其余每个系统上放置 1 个。如果主节点(即启动作业的节点)不在这些系统之中,则该节点上也会运行一个工作进程(共六个节点)。该指令与 Link 0 命令 %LindaWorkers 相对应,并可被其覆盖。-S- 指令指定用于启动工作进程的程序,其参数为 rsh(默认)或 ssh。

结合 SMP 与网络并行

当 -W- 与 -C- 或 -P- 结合使用时,会在节点列表中的每个节点上启动一个 SMP 并行工作进程(若为该节点指定了多个工作进程,则会启动多个此类进程)。换言之,这些单独的工作进程会依据 SMP 相关设置并行运行。如果这些设置不适用于某台列出的计算机,则该节点上的作业将失败。例如,以下指令会在指定系统上以多处理器作业的方式启动工作进程:

```
-W-alpha,beta,gamma
-C-0,1,2,3
```

但是,如果系统 *beta* 是双核工作站,该工作进程将失败,因为该计算机上不存在处理器 2 或 3。此机制主要为具有统一节点的集群环境而设计。请注意,起作用的是主节点上的 *Default.Route* 文件;工作节点上可能存在的 *Default.Route* 文件不会被使用。

GPU 上的并行执行

-G- 指令设置默认使用的 GPU 列表。使用 GPU 时,每个 GPU 必须由特定 CPU 控制,并且最好该 CPU 在物理上靠近其所控制的 GPU。列表采用 *gpu#(s)=core#(s)* 语法,用以指明使用哪些 GPU,以及每个 GPU 绑定到的核心。

例如,下面的指令让 Gaussian 在 GPU0 至 GPU3 上执行:

```
-G-0,1,2,3=0,1,16,17
```

GPU0 和 GPU1 绑定到核心 0 和 1,而 GPU2 和 GPU3 分别绑定到核心 16 和 17。该指令中可以使用 GPU 和/或核心的范围。例如,下面的写法与上面等价:

```
-G-0-3=0-1,16-17
```

#### 4.9.3 formchk 指令

-F- 指令设置 formchk 实用程序的默认选项。默认情况下,formchk 生成的格式化检查点文件与所有早期版本的 Gaussian 向后兼容。-F- 的参数可以是 -3 或 -2,以生成相应版本的格式化检查点文件(默认为版本 3)。参数中还可以包含 -c,此时分子力学原子类型会在格式化检查点文件中以字符串而非整数形式出现。内存指令 -U- 用于设置 formchk、freqchk 等实用程序中使用的默认内存。

#### 4.9.4 示例

对于一台拥有 8 GB 内存和 1 TB 磁盘的双核工作站,默认算法和内存分配已经合适。但需要指定 MaxDisk 以及默认使用的 CPU:

```
-C-0,1
-#-MaxDisk=200GB
```

对于一台拥有 4 颗八核处理器和 256 GB 内存、专为大型作业设计的服务器,默认应使用 8 个核心:从核心 0 开始的前 8 个奇数编号核心。此外,每个作业应分配更多内存(每核心 2 GB):

```
-M-16GB
-C-0-16/2
-#-MaxDisk=500GB
```

对于某些较旧的 Intel 处理器(Nehalem 及更早),其内存带宽不足以让芯片上的所有 CPU 保持忙碌,因此通常更适合只使用一半的 CPU,并且每个 CPU 分配两倍的内存。例如,在一台拥有 4 颗 12 核芯片、128 GB 内存的机器上,CPU 0-11 位于第一颗芯片,12-23 位于第二颗,依此类推,则最好使用 24 个处理器(每颗芯片 6 个),并且每个分配 72/24=3 GB 内存,而不是使用全部 48 个、每个只有 1.5 GB 内存。相应的指令应为:

```
-M-72GB
-C-0-47/2
```

/2 表示每隔一个核心使用:即芯片 0 上的核心 0、2、4、6、8 和 10,芯片 1 上的核心 12、14、16、18、20 和 22,依此类推。

**Default.Route Link 0 选项 环境变量 说明**

-#- -r GAUSS_RDEF 路由段关键字列表。 -C- %CPU -c GAUSS_CDEF 多处理器并行作业的处理器/核心列表。 -F- GAUSS_FDEF formchk 实用程序的选项。 -G- %GPUCPU -g GAUSS_GDEF 用于 GPU 并行作业的 GPU=核心列表。 -H- GAUSS_HDEF 计算机主机名。 -M- %Mem -m GAUSS_MDEF Gaussian 作业的内存量。 -O- GAUSS_ODEF 单位(站点)名称。 -P- %NProcShared -p GAUSS_PDEF 多处理器并行作业的处理器/核心数。多数情况下已被 -C- 取代。 -R- -r GAUSS_RDEF 路由段关键字列表。 -S- %UseSSH -s GAUSS_SDEF 启动网络并行作业工作进程的程序:rsh 或 ssh。 -U- GAUSS_UDEF 实用程序的内存量。 -W- %LindaWorkers -w GAUSS_WDEF 网络并行作业的主机名列表。
