### 4.2 在 UNIX 下运行

所有输入和资源设置准备就绪后,即可运行程序。Gaussian 16 可以使用以下两种命令形式之一交互式运行:

**_g16_** *job-name*

**_g16_** *<input-file >output-file*

在第一种形式中,程序从 *job-name*.gjf 读取输入,并将输出写入 *job-name*.log。若未指定 *job-name*,程序则从标准输入读取,并写入标准输出,二者可按常规 UNIX 方式进行重定向或管道连接。两种命令形式均可像其他 shell 命令一样,使用 & 符号放到后台运行。

#### 4.2.1 脚本与 Gaussian

用于运行 Gaussian 16 的脚本也可以通过多种方式创建。首先,可以在 shell 脚本中包含上述 g16 命令。其次,可以使用 « 结构在脚本中直接包含 Gaussian 输入:

```
#!/bin/sh
```

```
g16<<END>water.log
%Chk=water
#RHF/6-31G(d)
waterenergy
01
O
H11.0
H11.02120.0
END
echo"Jobdone."
```

« 符号之前的所有行都作为 g16 命令的输入。最后,可以创建循环以依次运行多个 Gaussian 作业。例如,以下脚本运行所有作为其命令行参数指定的 Gaussian 输入文件,并将其活动记录保存在文件 Status 中:

```
#!/bin/sh
echo"CurrentJobStatus:">Status
forfilein$argv;do
nam=‘echo$file|sed’s/\..*$//’‘
echo"Startingfile$fileat‘date‘">>Status
g16<$file>$nam.log
echo"$fileDonewithstatus$status">>Status
done
echo"AllDone.">>Status
```

以下较为复杂的脚本根据作为脚本命令行参数给出的部分输入文件动态生成 Gaussian 输入文件。这些部分输入文件缺少完整的路由段;其路由段仅包含一个 # 符号,或包含该分子体系所需特殊关键字的 # 行,但没有方法、基组或计算类型。脚本会为每个部分输入文件创建一个两步作业——先进行 Hartree-Fock 优化,再进行 MP2 单点能计算——其内容既包括脚本中的字面命令,也包括脚本执行时指定的各文件内容。脚本利用 Gaussian 16 的 include 文件机制来引入后者:

```
#!/bin/sh
echo"CurrentJobStatus:">Status
forfilein$argv;do
echo"Startingfile$fileat‘date‘">>Status
nam=‘echo$file|sed’s/\..*$//’‘
g16<<END>$nam.log
%Chk=$nam
#HF/6-31G(d)FOpt
@$file/N
--Link1--
```

```
%Chk=$nam
%NoSave
#MP2/6-31+G(d,p)SPGuess=ReadGeom=AllCheck
END
echo"$fileDonewithstatus$status">>Status
done#endoffor...do
echo"AllDone.">>Status
```

#### 4.2.2 使用 NQS 进行批处理运行

在支持 NQS 批处理设施的 UNIX 系统上,可以使用该设施运行 Gaussian。初始化文件中定义的 subg16 命令可将输入文件提交到批处理队列。其语法如下:

**subg16** *queue-name job-name* [`-scrdir` *dir1*] [`-exedir` *dir2*] [`-p` *n*]

两个必需参数为队列名和作业名。与交互式运行一样,输入取自 *job-name*.gjf,输出写入 *job-name*.log。NQS 日志文件发送到 *job-name*.batch-log。可选参数 -scrdir 和 -exedir 分别用于覆盖默认的临时文件目录和可执行文件目录。其他参数均视为 NQS 选项。特别地,-p *n* 可用于将作业在队列中的优先级设为 *n*。这是启动优先级(1 为最低),不影响运行时优先级。要从交互式会话提交 NQS 作业,应创建如下文件(文件名为 *name*.job):

```
#QSUB-rname-oname.out-eo
#QSUB-lt2000-lT2100
#QSUB-lm34mw-lM34mw
g16<name.gjf
```

其中 *name* 应替换为适合您计算的名称。第一行为运行中的作业命名、为输出文件命名,并使错误信息包含在输出文件中。时间参数有所不同,以便增加作业控制功能,例如在作业超出时间限制时归档检查点文件以进行清理。内存参数既用于作业的初始调度,也供程序确定动态内存使用量。随后通过执行命令 $ **qsub** *name***.job** 提交此作业,输出将放置在当前工作目录中。
