### 4.5 并行作业

#### 4.5.1 共享内存多处理器并行执行

Gaussian 默认仅在单个处理器上执行。如果您的计算机系统具有多个处理器/核心,并且您所使用的 Gaussian 版本支持并行处理,则可以使用 %CPU link 0 命令指定程序运行所在的具体 CPU。例如,以下设置表示程序应在六核系统的前 5 个核心上运行(保留一个核心供其他用途):

```
%CPU=0,1,2,3,4
```

节点列表也可以用范围表示(例如 0-5)。范围后还可以加上形式为 /*n* 的后缀,表示使用该范围内每第 n 个处理器(例如 /2 表示每隔一个处理器/核心)。较旧的 %NProcShared link 0 命令可用于指定用于执行的处理器总数(具体选择哪些处理器交由操作系统决定)。显然,所请求的处理器数目不应超过可用的处理器数目,否则将导致性能大幅下降。

#### 4.5.2 集群/网络并行执行

可以使用 Linda 并行执行环境,使作业跨越局域网中的离散系统或集群中的节点运行。HF、CIS=Direct 以及 DFT 计算均支持 Linda 并行,包括能量、优化和频率计算。TDDFT 能量与梯度以及 MP2 能量与梯度同样支持 Linda 并行。MP2 频率与 CCSD 计算的部分内容支持 Linda 并行,其余部分则仅支持 SMP 并行。要使 Linda 并行作业成功执行,必须满足以下条件:

- 您已执行相应的 Gaussian 16 初始化文件($g16root/g16/bsd/g16.login 或 $g16root/g16/bsd/g16.profile)。可以通过在主节点上运行一个串行 Gaussian 16 计算来测试此项。
- 所有节点都能够访问目录 $g16root/g16。
- 已设置 LD_LIBRARY_PATH 环境变量,以便定位 Linda 共享库。
- 如有需要,每个节点上应有本地临时空间(通过 GAUSS_SCRDIR 环境变量指定)。
- 程序将运行的所有节点均被当前主机信任。您应能够使用 rsh 或 ssh 命令远程登录,而无需向每个节点输入密码。关于网络中节点的安全配置,请联系系统管理员。每个节点都需要能够访问 Gaussian 16 目录树。推荐的配置是在参与并行作业的每个系统上都安装 G16。注意,Linda 二进制文件在每台机器上的路径必须相同。如果无法做到这一点,可以通过 NFS 挂载的磁盘使 G16 目录树可访问,该磁盘需在所有节点上挂载于相同位置。对于 MP2 计算,每个节点还必须有一些本地磁盘供 Gaussian 16 存放临时文件。这同样通过 GAUSS_SCRDIR 环境变量定义,应在每个节点上您账户的 .cshrc 或 .profile 中设置。%LindaWorkers 指令用于指定 Linda 工作进程应运行的计算机。其语法如下:

**%LindaWorkers**=*node1*[:*n1*][,*node2*[:*n2*]] [···]

此处列出每个要使用的节点的 TCP 节点名。默认情况下,每个节点启动一个 Linda 工作进程,但可选的数值允许对此进行调整。作业启动所在的节点(主节点)始终会启动一个工作进程,无论其是否出现在节点列表中。例如,以下指令会使一个

网络并行作业跨越指定的 5 个节点运行。节点 *hamlet* 和 *ophelia* 各运行两个工作进程。

```
%LindaWorkers=hamlet:2,ophelia:2,laertes,horatio,lear
```

默认情况下,Linda 使用 rsh 在节点之间通信。您可以在作业文件中加入以下 Link 0 选项,改用 ssh:

```
%UseSSH
```

最后,您还可以在主节点上创建一个名为 .tsnet.config 的配置文件,其中包含以下一行:

```
Tsnet.Node.lindarsharg:ssh
```

这将使用 ssh 代替。该文件可以放在您的主目录中,也可以放在您启动计算的目录中。%UseRSH 指令同样受支持,其作用是在 *Default.Route* 中已将 ssh 设为默认时,指定改用 rsh(见下文)。注意,在所有情况下,都必须事先配置好从主节点到所有工作节点的免密码 ssh 登录。一些有时较为有用的 Linda 选项如下:

```
-v Display verbose messages
-vv Display very verbose messages
```

可以使用 GAUSS_LFLAGS 环境变量来设置它们。例如,可以通过以下命令开启非常详细的 Linda 输出:$ **export GAUSS_LFLAGS="-vv"**

也可以通过在作业中加入 %DebugLinda link 0 命令来开启详细输出选项。

Linda 还有许多其他选项,但大多数并不被 Gaussian 使用。在 GAUSS_LFLAGS 中可以使用 -opt *option* 形式来调用任何有效的 .tsnet.config 文件指令。注意,Gaussian 16/Linda 不使用原生 Linda 资源 *minworker* 和 *maxworker*。

#### 4.5.3 结合共享内存与网络/集群并行

以下 link 0 命令会在主机 *norway* 和 *italy* 上各启动一个四路并行工作进程,并在 *spain* 上启动两个此类工作进程:

```
%CPU=0-3
%LindaWorkers=norway,italy,spain:2
```

当 *norway* 和 *italy* 为 4 处理器/核心计算机,而 *spain* 为 8 处理器/核心计算机时,这些 link 0 命令是合适的。

在节点内部始终最好使用 SMP 并行,而仅在节点之间使用 Linda。例如,对于一个由 4 个节点组成的集群,每个节点配备双路四核 EM64T 处理器,应使用如下设置(而不是每个节点使用多个 Linda 工作进程):

```
%CPUs=0-7
%LindaWorkers=node1,node2,node3,node4
```

#### 4.5.4 启动与监控并行 Gaussian 16 作业

完成适当的设置后,即可像平常一样使用 g16 命令启动并行 Gaussian 16 作业:$ **g16 input.gjf &** 对于分布式并行计算,Gaussian 16 将根据需要启动主进程和工作进程。Linda 并行的文件名形式为 *.exel*。在工作节点上使用 top 或其他命令,可以在 *xxx*.exel 文件启动时看到它。并行计算的相关性能指标是实际耗时(elapsed 或挂钟时间)。最简单的检查方法是使用外部监视工具,例如 time、times 或 timex,例如:$ **times g16 input.gjf &** 该命令将报告 Gaussian 作业的实际耗时、CPU 时间和系统时间。注意,后两者仅与主节点相关,每个节点上消耗的 CPU 时间和系统时间量相近。并行加速比为串行作业的实际耗时与并行作业的实际耗时之比。
